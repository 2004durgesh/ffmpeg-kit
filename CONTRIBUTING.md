# Contributing

Contributions are welcome. Please read the [code of conduct](./CODE_OF_CONDUCT.md) first.

## Repository layout

The repo root is the npm package `react-native-ffmpeg-kit`, a [Nitro Module](https://nitro.margelo.com) with a shared C++ core.

| Path | What it is |
|---|---|
| `src/specs/` | Nitro specs, the source of truth for the native surface |
| `src/` | The public TypeScript API; `index.ts` only re-exports |
| `cpp/` | Shared C++ core: sessions, running FFmpeg, logs, statistics, cancel |
| `android/`, `ios/` | Platform code: Kotlin and Swift for platform services, plus a small hot-path file each |
| `nitrogen/generated/` | Generated by `yarn nitrogen`. It's committed, so don't edit it by hand |
| `example/` | Example app that runs an on-device test suite |
| `ffmpeg/` | The FFmpeg binary build, kept separate from the package (see below) |

## Development workflow

Use the Node version in [`.nvmrc`](./.nvmrc). The repo is a Yarn 4 workspace, so use `yarn`, not npm:

```sh
yarn                 # installs the package and example dependencies
```

When you change a `*.nitro.ts` spec, regenerate the native bindings and implement the changes in `cpp/` (or in the Kotlin/Swift platform code):

```sh
yarn nitrogen
```

Run the checks:

```sh
yarn test            # Jest: characterization and contract tests against a fake native layer
yarn typecheck       # also fails if the fake drifts from the specs
```

Run the example app. On launch it runs real FFmpeg through the public API and reports `11/11 passed` (see [example/README.md](./example/README.md)):

```sh
yarn example start
cd example/ios && pod install && cd ../..
yarn example ios
yarn example android
```

JavaScript changes reload without a rebuild. Native changes (`cpp/`, `android/`, `ios/`, the podspec or `build.gradle`) need a rebuild of the example app.

## The FFmpeg binaries

The package downloads prebuilt FFmpeg from this repo's GitHub releases (`ffmpeg-android-*` and `ffmpeg-ios-*` tags). `ffmpeg/` builds those binaries. Only touch it when the native FFmpeg build itself changes.

- CI builds them when you push a matching tag (`.github/workflows/*-ffmpeg-binaries.yml`). A build takes hours.
- To build the Android AAR locally, use the Docker builder in [`ffmpeg/tools/docker`](./ffmpeg/tools/docker/README.md).
- Run `ffmpeg/android.sh` and `ffmpeg/ios.sh` for local builds. They resolve every path from their own folder.

## Commit messages

Follow [Conventional Commits](https://www.conventionalcommits.org): `fix:`, `feat:`, `refactor:`, `docs:`, `test:`, `chore:`. The changelog is generated from them, so mark breaking changes with `!` and a `BREAKING CHANGE:` footer.

## Pull requests

- Keep each pull request focused on one change.
- Make sure `yarn test`, `yarn typecheck` and the example app pass.
- For API or behaviour changes, open an issue first to discuss them.
